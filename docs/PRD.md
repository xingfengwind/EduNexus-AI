# EduNexus AI 产品需求文档（PRD）

版本：V1.0 草案
日期：2026-11-10
产品定位：校级教学资料智能处理与知识服务平台
依据：本地软件总体设计说明书 docs/EduNexus_AI.md（原文不随本次提交发布）（V1.0 方案基线稿）

## 1. 文档范围与决策状态

本文将总体设计基线转化为可实施、可验收的产品需求，覆盖完整产品范围，不表示所有模块在首期交付。原文已确认的角色、权限、技术栈和业务约束保持一致；本文新增的页面组织、验收场景和状态表达属于需求细化建议。数值指标、身份审核、考试策略等未确认事项集中列于第 12 节，须在对应阶段实施前确认。

## 2. 背景、目标与边界

校内教学资料分散、处理成本高、课程资源和教学活动缺少关联。平台以资料为入口，贯通资料处理、知识沉淀、资源审核、课程共享、练习考试和学习反馈。

目标：统一校级身份和组织授权；建立个人、院系和课程资源边界；集中管理 AI 能力；形成教学闭环；提供可追踪、可恢复的处理过程。

本期产品形态为适配桌面、平板、手机浏览器的响应式 Web。范围包括九个业务模块和七类 AI 工具。原生客户端、教务系统替代、收费支付、跨校多租户以及无人审核的正式教学发布不纳入当前基线；如需增加，另行评审。

AI 输出为辅助内容。正式教学资源、重要成绩及关键教学管理操作必须遵循人工审核或业务确认规则。

## 3. 用户与权限

| 角色 | 核心任务 | 数据边界 |
| --- | --- | --- |
| 教师 | 建课、审核 AI 内容、发布资源、作业考试、批改和成绩确认 | 本人资料、获授权院系资源、本人创建或获授权管理的课程 |
| 学生 | 加课、学习、AI 辅助、练习、作业、考试和讨论 | 本人资料和学习记录、已加入课程中开放的资源活动 |
| 管理员 | 账号组织权限、模型配置、系统运维和审计 | 系统管理授权范围；不默认读取私人资料及问答正文 |
| 教学管理人员 | 教学监督、课程资源统计和院系分析 | 授权学校或院系范围，以汇总数据为主 |

支持多角色账号和不同课程身份。采用角色权限、组织范围、课程关系、资源授权共同决策。前端隐藏入口不能代替服务端授权。

自主注册不授予教师、管理员或教学管理权限。管理员和教学管理角色须由有权人员分配。默认账号角色、学生核验和教师审核流程待确认。

资料默认私有；教师可主动选择院系共享，院系共享不等于全校公开。学生资料仅在主动授权或按课程规则提交后供相应对象访问。

## 4. 产品入口与主要旅程

建议主导航：工作台、个人资料库、AI 工具与任务、我的课程、教学资源中心、教学与学习、课程互动、学习分析、系统管理。入口随角色授权展示；课程内包含资源、成员、教学计划、作业考试、讨论公告和分析。

教师旅程：登录 → 上传资料 → 创建解析或 AI 任务 → 查看进度和结果 → 审核修改 → 发布到授权范围 → 布置教学活动 → 批改确认 → 查看课程分析。

学生旅程：注册与必要核验 → 邀请码加入或申请审核 → 阅读资源与知识点 → 授权资料问答 → 练习、作业或考试 → 查看已公布成绩、错题和学习反馈。

管理员旅程：配置组织角色 → 处理身份审核 → 配置模型与存储 → 查看任务运行、调用统计和审计 → 处理失败及恢复。

阶段编号对应第 11 节。以下均为目标产品需求，阶段决定交付顺序。

| 编号 | 模块 / 阶段 | 需求与业务规则 | 核心验收条件 |
| --- | --- | --- | --- |
| FR-01 | 用户组织 / 1 | 注册登录、密码管理、身份审核、账号停用、学校院系专业年级班级、角色和数据范围 | 普通账号不能自行提权；无权接口被拒绝；停用和身份变更有审计；会话支持撤销 |
| FR-02 | 个人资料库 / 1 | PDF、Word、PPT、TXT、MD 上传和批量上传、分类、预览、下载、删除、版本、共享、处理历史 | 不支持格式和超限文件有明确提示；私有文件不能被他人读取；删除检查关联并反馈原因；历史版本可区分 |
| FR-03 | AI 工具 / 2 | 七类工具统一入口、参数校验、结果展示、来源与审核信息、课程 AI 助手入口 | 工具真实执行；失败不得伪装成功；用户只可处理有权资料；正式发布受审核约束 |
| FR-04 | AI 任务 / 2 | 提交、进度、状态、结果引用、失败原因、重试、超时及取消记录 | 重复消息不重复创建正式资源；失败可定位；重试次数可追踪；未授权任务不可查看 |
| FR-05 | 课程 / 1 | 创建编辑、负责人、课程状态、邀请码、申请审核、成员管理、资料关联、发布撤回 | 学生只能访问已加入且开放的内容；申请经教师审核后生效；邀请码与审核方式均可用 |
| FR-06 | 教学资源 / 3 | 资料、知识点、题库、分类共享、审核、发布撤回和版本；AI 审核基础能力在阶段 2 交付 | 未审核 AI 草稿不进入正式发布范围；撤回后检索与直接访问均受限；题目保留来源和版本 |
| FR-07 | 教学学习 / 3、4 | 自由练习、作业、练习式和正式式考试、自动保存、交卷、批改、成绩和错题；计划在阶段 4 完善 | 发布考试固定试卷和题目版本；题库修改不影响已发布考试；到时交卷；成绩教师确认后公布 |
| FR-08 | 互动消息 / 1、4 | 阶段 1 提供消息基础；阶段 4 完成讨论、师生及 AI 问答、公告、指定成员通知、已读状态 | 非课程授权对象不能访问；通知接收人符合授权范围；已读状态准确；私密提问策略待确认 |
| FR-09 | 学习分析 / 4 | 学习记录、正确率、成绩、知识点掌握、错题、趋势、教师课程统计和院系汇总 | 学生仅看本人记录；教师及管理人员按授权范围查询；指标显示口径及时间范围，不泄露私密正文 |
| FR-10 | 系统管理 / 1—5 | 用户权限、模型/API、使用统计、存储、参数、操作日志、监控和导出公共能力逐步建设 | 密钥不下发前端；重要配置变更可追踪；导出遵循原数据权限；可查看健康、积压和异常 |

### 5.1 七类 AI 工具

| 工具 | 输入 | 输出与专属验收 |
| --- | --- | --- |
| 文档智能问答 | 问题、有权文档或知识库 | 回答带资料引用；无充分依据时明确提示，不能编造来源 |
| 知识点提取 | 课程资料、章节 | 结构化知识点、层级、来源位置；教师审核后纳入正式资源 |
| 习题智能生成 | 知识点、章节、题型、难度 | 题目、选项（适用时）、答案和解析；教师可修改审核后发布 |
| 资料智能检索 | 关键词、自然语言 | 关键词、语义或混合结果；返回前再次验证权限 |
| PPT 内容提取 | PPT 文件 | 逐页文本、提纲、摘要；结果保持页序关联 |
| Word 教案整理 | Word 或教学素材 | 教案结构、教学目标、重难点；结果可供人工审阅 |
| PDF 智能标注 | PDF 文件 | 重点、批注建议、页码或文本位置；原文件保留 |

共同要求：展示任务状态，标记 AI 生成属性、模型信息、生成时间、来源和审核状态。损坏、加密或无法解析的文档应明确提示；是否支持 OCR 及具体覆盖范围由模型和解析器选型确认。资料内容作为输入数据处理，不得作为指令绕过权限或泄露其他资料。

### 5.2 作业、考试与成绩

教师选择题目、适用对象、时间和规则后发布。学生在允许时间答题，定期保存进度，主动提交或到时自动交卷。客观题自动判分，主观题人工批改，AI 只给评分建议。教师确认并公布成绩后更新错题和分析。成绩修改必须保留操作者、时间和变更记录。

重复提交、断线恢复、补考、申诉、考试模式差异和限时细节须在阶段 3 前形成明确规则；不能把实现默认值当作已确认产品规则。

## 6. 状态与异常处理建议

下列为详细设计输入，状态名称与转换条件在接口设计时确认。

| 对象 | 建议状态 | 约束 |
| --- | --- | --- |
| AI 任务 | 待投递、排队、执行中、成功、失败、超时、已取消 | 重试保留历史；取消反馈真实执行结果；迟到或重复结果不得覆盖已确认业务状态 |
| 教学资源 | 草稿、待审核、退回、已发布、已撤回 | 仅授权人员审核发布；来源、版本和审核记录可追溯 |
| 加课申请 | 待审核、已通过、已拒绝 | 重复请求不重复建立成员关系 |
| 考试答卷 | 未开始、答题中、已提交、待批改、已批改 | 正式成绩公布由教师确认控制；发布题目版本保持不变 |

文件上传失败允许重新上传；解析失败保留原文件并给出原因；模型超时、额度不足和任务积压提供可理解提示。空列表应给出适合当前角色的下一步入口。共享撤回或权限变化后，下载、检索、问答和导出均重新校验权限。

## 7. 数据与系统约束

正式业务对象包括用户组织角色、文件及版本授权、课程成员申请、知识点习题审核、试卷题目快照、答卷成绩、任务、消息及审计。具体字段、接口和物理表另行设计。

已确认架构：Java 模块化单体管理主业务；Python 独立处理 AI 计算。普通模块采用 MVC，复杂模块采用 DDD 思想分层。模块只能经公开接口或事件协作，不跨模块直接写业务表。

| 领域 | 已确认技术与职责 |
| --- | --- |
| Web | Vue 3、TypeScript、Vite、Element Plus；Pinia、Vue Router、Axios |
| 主业务 | Spring Boot、Spring Security + JWT、MyBatis |
| AI | FastAPI、Pydantic、LangChain；复杂有状态流程按需用 LangGraph |
| 权威业务数据 | MySQL；不因已安装 PostgreSQL 技能改变数据库选型 |
| 派生与辅助数据 | Redis 缓存；Elasticsearch 全文；Milvus 向量；MongoDB 解析 JSON 和适用的检查点 |
| 消息 | RabbitMQ；任务与待发事件先持久化，可靠投递、幂等消费、重试和死信处理 |
| 文件 | RustFS S3 兼容对象存储；MySQL 保存元数据与权限，统一文件服务封装 |
| 部署 | Docker / Docker Compose、Nginx、Git |

Python 不直接写 Java 核心业务表。长任务异步执行，前端用 SSE 或轮询展示进度。ES 和 Milvus 是可重建索引；向量过滤不能代替最终权限检查。文件和元数据写入失败须有补偿机制，不假定跨存储天然事务一致。

## 8. 安全、隐私与运维需求

- 密码安全单向哈希；访问令牌有有效期，刷新令牌有轮换、撤销策略。
- 资源和接口执行用户、院系、课程及资源授权；管理员身份不自动获得私人正文读取权。
- 私有文件禁止匿名公开访问；短时签名下载链接在服务端授权后生成，不记入普通日志。
- 上传校验扩展名、MIME、实际内容和大小，必要时扫描；对象键与原始名称分离。
- 向模型发送资料前授权并最小化数据；模型密钥安全注入或加密，不提交 Git，不暴露前端。
- 审计关键身份、权限、审核、发布、成绩和配置操作；日志避免保存敏感正文。
- 开发、测试、生产配置及凭据隔离；基础数据服务默认不直接暴露公网。
- 协调备份 MySQL 文件元数据与 RustFS 对象；持久化数据有恢复演练，索引有重建或快照能力。
- 监控服务健康、积压、失败率、调用耗时和关键异常；配置日志轮转、资源限制和健康检查。

## 9. 非功能与衡量指标

当前未确认用户容量、并发、响应时间、可用性和恢复数值，不能作为既定承诺。容量评估后补充目标、负载、测量方法及通过阈值。

| 类别 | 要求 / 测量口径 |
| --- | --- |
| 性能 | 常规操作流畅，长 AI 任务异步；分别测量常规接口 P95、排队等待和任务处理耗时 |
| 可靠性 | 重复投递不重复产生正式资源；故障可重试、可定位、可恢复 |
| 兼容性 | 桌面、平板和手机完成核心流程；浏览器版本矩阵上线前确认 |
| 可维护性 | 统一接口、异常、日志和分页；核心规则、权限、状态转换有测试 |
| AI 质量 | 固定授权评测集，评价检索命中、引用正确性和结构化输出有效性；阈值待定 |
| 产品成效 | 统计上传解析成功率、任务成功率、审核通过率、课程加入与学习任务完成率；试点后确定目标 |
| 隐私 | 跨用户、院系、课程越权场景均被拒绝；日志和管理报表不暴露未授权正文 |

## 10. 验收场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 学生尝试直接访问他人私有文件、任务和问答 | 接口拒绝，下载和搜索同样不能绕过 |
| AC-02 | 教师上传、生成知识点并发布 | 原文件可追踪，生成内容先待审核，审核后仅向选择范围开放 |
| AC-03 | 用户加入课程 | 邀请码方式和申请审核方式按配置生效，未加入者看不到受限资源 |
| AC-04 | AI 执行失败后重试，并重复投递同一消息 | 失败原因及历史可见，无重复正式资源 |
| AC-05 | 教师发布考试后修改题库 | 已发布试卷和既有答卷仍引用原版本 |
| AC-06 | 学生作答、交卷、批改、公布成绩 | 保存进度，到时交卷；主观题需教师处理；公布前不显示正式成绩 |
| AC-07 | 教师修改已公布成绩 | 变更记录可查，分析按确定口径更新 |
| AC-08 | 资源撤回、共享权限取消 | 后续直接访问、检索、AI 引用取用和导出被相应权限规则限制 |
| AC-09 | 管理员或教学管理人员查看统计 | 仅授权范围，不能凭管理身份读取私人资料和问答正文 |
| AC-10 | 备份恢复及索引重建演练 | 业务数据和对象关联一致，恢复和重建结果有记录 |

测试覆盖单元、接口、组件集成、权限、完整业务流程、AI 评测、响应式交互及安全恢复。文档验收不等同于软件功能已实现或测试已通过。

| 容量与兼容 | 用户并发、吞吐、时延、浏览器矩阵、资源预算 | 容量规划及上线前 |
| 保留恢复 | 对话日志文件考试保留期、恢复目标及演练频率 | 上线前 |

主要风险：AI 幻觉通过来源引用和人工审核控制；跨范围检索通过服务端二次授权控制；多组件部署复杂度通过分阶段接入与恢复演练控制；模型费用和吞吐通过额度、限流和监控控制；未决考试及身份规则可能影响排期，须在对应阶段前关闭。

## 13. 需求变更与追踪

FR 编号用于关联详细设计、接口、实现和测试；AC 编号用于关联验收记录。新增需求或修改基线须记录原因、影响模块、阶段和确认结果。总体设计与 PRD 出现冲突时先记录差异并确认，不由实现默默改变已确认方案。
