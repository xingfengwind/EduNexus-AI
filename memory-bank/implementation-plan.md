# EduNexus AI Implementation Plan

> 执行方式：逐项使用 executing-plans 执行；只有用户明确要求委派时才使用 subagent-driven-development。每项完成验证后再进入依赖它的任务。

**Goal:** 按 PRD 五阶段交付可部署、权限可控、AI 结果可审核的校级教学资料平台。

**Architecture:** Vue Web → Java 模块化单体；Python 独立 AI API/Worker。MySQL 管权威业务，RustFS 管文件，RabbitMQ + Outbox 管可靠事件，其他存储按职责分工。

**Tech Stack:** 以 [tech-stack.md](tech-stack.md) 为准；需求及验收见 [PRD.md](PRD.md)，设计见 [design-document.md](design-document.md)，协作规则见 [AGENTS.md](AGENTS.md)。

## 1. 执行约定

本文是待执行计划，不表示功能或测试已完成。所有复选框初始未完成。任务编号为追踪单位；每行只实施描述中的能力，执行时按下述微步骤继续拆分。一般一个微步骤控制在 2—5 分钟；超出时继续拆分测试场景，不能以一条任务包办整个模块。

功能和缺陷任务逐项执行：

- [ ] 写本行指定的失败测试，明确输入及预期，不写只验证实现细节的测试。
- [ ] 单独运行该测试，确认因缺少目标行为失败，而非依赖/语法错误。
- [ ] 实现使测试通过的最少代码。
- [ ] 重跑目标测试及直接受影响测试，确认全部通过；必要时重构后再验证。
- [ ] 更新进度和证据，审查 diff，显式暂存本任务文件，以 `feat/fix/test/refactor(scope): 描述` 提交。

纯文档、配置和工程初始化任务以链接、配置解析、构建或启动验证替代无意义单测，使用 docs/chore 前缀。每行“完成”还要求无凭据泄露、无跨模块直接写表、无相关回归；失败和阻塞记录在 memory-bank/progress.md，不勾选完成。

涉及未决产品规则的任务先执行对应决策门禁。可独立的基础任务继续推进，不把假定写成已确认规则。阶段结束验证全流程并评审后才能创建阶段 Tag，不自动合并 main、不强推。

## 2. 文件职责与测试位置

以下路径是将要创建的目标；当前尚未建立工程。Java 包根建议 `com.edunexus`，实际包名在 P00-02 锁定；下文 `backend/src/main/java/com/edunexus/` 简称 `J/`，测试根 `backend/src/test/java/com/edunexus/` 简称 `JT/`。每个模块内按设计采用 MVC 或领域分层。

| 路径 | 职责 |
| --- | --- |
| frontend/src/app/ | 路由、布局、会话协调 |
| frontend/src/modules/{domain}/ | 业务页面、API、类型及组件 |
| frontend/src/shared/ | HTTP、错误、权限显示和基础组件 |
| frontend/tests/unit/、frontend/tests/e2e/ | Vitest 组件/逻辑与 Playwright 用户流程 |
| backend/pom.xml、backend/.mvn/、backend/mvnw.cmd | Java 依赖与统一构建 |
| J/{domain}/、JT/{domain}/ | 模块实现与对应领域、接口、集成测试 |
| backend/src/main/resources/db/migration/ | Flyway 版本迁移，一次发布后不改旧脚本 |
| ai-service/app/{api,workers,providers,parsers,retrieval,workflows,schemas}/ | Python 服务与 AI 能力 |
| ai-service/tests/ | pytest 单元、契约、集成及 AI 评测 |
| contracts/openapi.yaml、contracts/events/ | 外部接口与跨语言事件 Schema |
| deploy/compose.yaml、deploy/nginx/、deploy/.env.example | 容器、入口和无敏感值的配置模板 |
| .github/workflows/ci.yml | 按语言及集成环境运行质量检查 |
| docs/decisions/、docs/verification/ | 决策与脱敏验证证据 |

接口和消息先更新契约再实现双方；表结构先迁移再 Mapper。测试数据全部合成，不能上传真实学生资料。

## 3. 验证命令约定

这些命令在工程建立后才可执行。P00 对应任务必须创建下面引用的 script/marker；不存在时先补齐，不把“命令未找到”当成通过。Windows 在相应子目录执行，Linux CI 使用等效 mvnw。

| 代号 | 工作目录与命令 | 成功标准 |
| --- | --- | --- |
| F | frontend：`npm run lint`、`npm run typecheck`、`npm run test:unit -- --run`、`npm run build` | 全部退出 0，无相关失败 |
| E | frontend：`npm run test:e2e -- --grep <任务编号>` | 对应带编号测试通过，依赖服务已启动 |
| J | backend：`./mvnw.cmd verify` | 单元和集成均执行且通过；集成测试通过 Failsafe 绑定 verify，禁止跳过 |
| JT | backend：`./mvnw.cmd -Dtest=<测试类> test` | 目标单测通过；提交前再运行 J |
| P | ai-service：`uv run ruff check .`、`uv run ruff format --check .`、`uv run pytest` | 静态检查与测试通过；集成标记不默认跳过 |
| PT | ai-service：`uv run pytest tests/<目标文件>.py -q` | 目标测试通过；受影响契约与集成测试同时运行 |
| C | 根目录：`docker compose -f deploy/compose.yaml config --quiet` | 配置有效；另外启动目标 profile 并确认健康及功能探针 |
| D | 根目录：`git diff --check`；提交前 `git diff --cached --check` | 无格式问题；内部链接存在；显式核对暂存文件清单 |

AI 真实供应商评测与离线单测分开：离线使用确定性合成结果验证程序，真实评测必须有获授权模型、额度、脱敏样本和明确阈值。缺少凭据标记阻塞，不能用 mock 通过冒充真实能力通过。
